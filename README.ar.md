اتصل بأجهزة أندرويد عبر Wi-Fi من قائمة شريط النظام أو من سطر الأوامر. يدعم عدة
أجهزة في وقت واحد، ويحافظ على الاتصال عبر انقطاع الشبكة وإعادة التشغيل، ويعرض
شاشة الجهاز عبر scrcpy.

## كيف يتم الاتصال

أضافت أندرويد 11 خدمة "التصحيح اللاسلكي" (Wireless debugging): خدمة TLS يعلن
عنها الهاتف عبر mDNS على منفذ يتغيّر بعد كل إعادة تشغيل وكل تبديل للواي فاي.
أما الطريقة الأقدم `adb tcpip <port>` فهي تعيد تشغيل `adbd` على الهاتف، وإعادة
التشغيل هذه تُسقط جلسة التصحيح اللاسلكي وتترك المفتاح في خيارات المطوّر مغلقًا.

لذلك تختار الأداة المسار المناسب لكل جهاز:

| حالة الجهاز | المسار المستخدم | الأثر على الهاتف |
|-------------|------------------|------------------|
| أندرويد 11+ ويعلن عن نفسه عبر mDNS | الاتصال بالمنفذ المعلن | لا شيء يتغيّر |
| أندرويد 11+ والمفتاح مغلق | محاولة تفعيل `adb_wifi_enabled` ثم انتظار الإعلان | يُفتح المفتاح إن سمح المصنّع |
| أندرويد 11+ والمفتاح مفتوح بلا إعلان بعد | انتظار الإعلان | لا شيء يتغيّر |
| أندرويد 10 أو أقدم، أو لا يوجد دعم mDNS | العودة إلى `adb tcpip` | يُعاد تشغيل `adbd` ثم يُعاد المفتاح إلى التشغيل |

تفعيل المفتاح من adb محاولة قدر الإمكان لا أكثر. الأمر `settings put global
adb_wifi_enabled 1` ينتهي بنجاح ظاهري حتى عندما يتجاهل النظام الكتابة، وعدة
مصنّعين يفعلون ذلك تحديدًا: المفتاح مُصمَّم ليكون بيد المستخدم، وأندرويد لا
يوفّر أمرًا رسميًا لتفعيله. لذلك تقرأ الأداة القيمة بعد الكتابة، وإن لم تثبُت
أبلغتك وطلبت منك تفعيله يدويًا بدلًا من التظاهر بالنجاح.

الفصل يحدث دائمًا من جهة الحاسب فقط: `adb disconnect` بلا `adb usb` وبلا
`adb tcpip`. مفتاح التصحيح اللاسلكي يبقى كما تركته تمامًا.

### إعادة الاتصال

إعلان mDNS يبقى موجودًا بعد اختفاء الخدمة التي يصفها، فرفض الإعلان لا يعني أن
الجهاز غير موجود. تُجرَّب العناوين بهذا الترتيب:

1. العنوان المعلن حاليًا عبر mDNS لذلك الرقم التسلسلي.
2. العنوان المحفوظ له في المرة السابقة.
3. المنفذ الثابت (5555 افتراضيًا) على كل مضيف ظهر أعلاه، وهو المكان الذي يظل
   يستمع فيه جهاز حُوِّل إلى اللاسلكي بالطريقة القديمة.

كل اتصال يُتحقَّق منه قبل الإبلاغ عن نجاحه: تنفّذ الأداة أمرًا حقيقيًا على
الجهاز وتقارن الرقم التسلسلي مع الجهاز المطلوب، فإن كان عنوان الشبكة قد انتقل
إلى هاتف آخر يُرفَض الاتصال بدلًا من قبوله بصمت. والعناوين التي ترفض الاتصال أو
لا يمكن الوصول إليها تفشل فورًا ويُجرَّب المرشّح التالي، بدل استهلاك كل
المحاولات.

## التثبيت

لينكس وماك:

```bash
git clone https://github.com/ALSRKAL/adb-wireless-manager.git
cd adb-wireless-manager

./install.sh                 # الأيقونة فقط
./install.sh --with-watch    # الأيقونة مع خدمة إعادة الاتصال بالخلفية
```

ويندوز:

```powershell
git clone https://github.com/ALSRKAL/adb-wireless-manager.git
cd adb-wireless-manager
powershell -ExecutionPolicy Bypass -File install.ps1
```

يتحقّق المثبّت من adb وscrcpy وPyQt5، ويسجّل الأيقونة لتعمل مع بدء الجلسة،
ومع `--with-watch` ينشئ خدمة systemd تحافظ على اتصال الأجهزة بالخلفية.

## الاستخدام

### أول مرة مع جهاز جديد

الكابل مطلوب مرة واحدة فقط لتخويل هذا الحاسب.

1. وصّل الجهاز بـ USB واقبل نافذة التصحيح على شاشته.
2. من قائمة الأيقونة: `توصيل جهاز عبر USB`. أو من سطر الأوامر:

```bash
./scripts/adbconnect.sh connect                    # لينكس وماك
powershell -File scripts\adbconnect.ps1 connect    # ويندوز
```

3. اسحب الكابل. الجهاز محفوظ الآن.

على أندرويد 11 وأحدث يمكنك تجاوز الكابل تمامًا: استخدم
`اقتران لاسلكي (بدون كابل)` من الأيقونة، أو `adbconnect.sh pair`.

### بعد ذلك

من الأيقونة: اضغط عليها، فتظهر كل الأجهزة المعروفة، كل جهاز مرة واحدة مع وسيلة
اتصاله الحالية. استخدم `إعادة اتصال الكل`، أو افتح جهازًا غير متصل واختر
`إعادة الاتصال الآن`.

من سطر الأوامر:

```bash
./scripts/adbconnect.sh reconnect    # اكتشاف mDNS مع المنافذ المحفوظة
./scripts/adbconnect.sh watch        # حلقة الإصلاح
./scripts/adbconnect.sh list         # أجهزة adb الحالية
./scripts/adbconnect.sh disconnect   # فصل الاتصالات اللاسلكية على هذا الحاسب
./scripts/adbconnect.sh doctor       # تشخيص البيئة
./scripts/adbconnect.sh pair         # اقتران لاسلكي لأندرويد 11+
```

### ماذا يصمد أمام ماذا

| الحدث | النتيجة |
|-------|---------|
| انقطعت الشبكة ثم عادت | خدمة المراقبة أو الأيقونة تعيد الاتصال |
| أعدت تشغيل الحاسب | الأيقونة وخدمة المراقبة تتصلان عند تسجيل الدخول |
| أعدت تشغيل الهاتف | منفذه اللاسلكي يتغيّر، والاكتشاف عبر mDNS يجد المنفذ الجديد |
| فصلت جهازًا بنفسك | يبقى مفصولًا حتى تعيده أنت، وحلقة الإصلاح تتجاهله |
| ألغيت الاقتران من الهاتف | نفّذ `pair` أو وصّل الكابل مرة أخرى |

## الإعدادات

تشترك الأيقونة وسطر الأوامر في الملف `~/.config/adbconnect/settings.json` الذي
تكتبه نافذة إعدادات الأيقونة. كما يقرأ سكربت bash قيم `KEY=VALUE` من
`~/.config/adbconnect/config`:

| المفتاح | الافتراضي | المعنى |
|---------|-----------|--------|
| `START_PORT` | 5555 | أول منفذ لمسار tcpip الاحتياطي |
| `MAX_RETRIES` | 3 | عدد محاولات الاتصال لكل عنوان |
| `CONNECT_TIMEOUT` | 6 | ثوانٍ لكل `adb connect` |
| `MDNS_WAIT` | 20 | ثوانٍ انتظار إعلان mDNS |
| `WATCH_INTERVAL` | 20 | ثوانٍ بين دورات الإصلاح |
| `AUTO_SCRCPY` | true | تشغيل scrcpy بعد نجاح الاتصال |
| `SCRCPY_ARGS` | فارغ | خيارات إضافية لـ scrcpy |
| `PREFER_IFACES` | wlan,wifi,eth,ap | ترتيب الواجهات عند اختيار العنوان |
| `LANG_CODE` | auto | `ar` أو `en` أو `auto` |

الأجهزة المحفوظة في `~/.local/share/adbconnect/devices.tsv`، وعلى ويندوز في
`%APPDATA%\adbconnect`. صف واحد لكل جهاز، مفتاحه الرقم التسلسلي.

## هيكل المشروع

```
adb-wireless-manager/
  scripts/
    adbconnect.sh      سطر أوامر POSIX (لينكس، ماك، BSD)
    adbconnect.ps1     سطر أوامر ويندوز (PowerShell 5+)
  tray/
    adbtray.py         تطبيق أيقونة Qt متعدد المنصات
  tests/
    test_core.py       اختبارات وحدة لا تحتاج جهازًا
    run_tests.sh       تحليل ثابت مع اختبارات الوحدة
  install.sh           مثبّت لينكس وماك
  uninstall.sh         مزيل التثبيت
  install.ps1          مثبّت ويندوز
  requirements.txt     اعتماديات بايثون
```

## الاختبارات

```bash
./tests/run_tests.sh          # تحليل ثابت مع اختبارات الوحدة
LIVE=1 ./tests/run_tests.sh   # مع فحص حي لـ adb والخدمة والأيقونة
```

تغطي اختبارات الوحدة استراتيجية الاتصال، ودمج هوية الأجهزة الذي يمنع تكرار
الصفوف في القائمة، وإزالة التكرار من ملف الأجهزة، ومحلّلات المخرجات، وبناء
الواجهة بدون شاشة. كما تحرس قاعدتين على مستوى الكود: لا مسار ينفّذ `adb usb`،
ولا ملف مُوزَّع يحتوي رموزًا تزيينية.

## حل المشاكل

| المشكلة | الحل |
|---------|------|
| رسالة `unauthorized` | افتح قفل الهاتف واقبل نافذة التخويل |
| التصحيح اللاسلكي يُغلق من تلقاء نفسه | أُصلح في 14.0.0: لم تعد الأداة تعيد تشغيل `adbd` على أندرويد 11+، وتعيد المفتاح إلى التشغيل عند اللجوء إلى tcpip |
| ظهر الهاتف نفسه مرتين في القائمة | أُصلح في 14.0.0: تُدمج الصفوف حسب الرقم التسلسلي، وتُصلَح الملفات المكرَّرة القديمة عند القراءة |
| الأداة تقول إنها لم تستطع تفعيل التصحيح اللاسلكي | المصنّع يمنع كتابة الإعداد. فعّل المفتاح من خيارات المطوّر، وكل ما عدا ذلك يعمل بشكل طبيعي |
| فشل إعادة الاتصال بعد إعادة تشغيل الهاتف | منفذه تغيّر، و`reconnect` يجد الجديد عبر mDNS إن كانت نسخة adb تدعمه |
| رسالة `Nothing is listening on <العنوان>` | إعلان mDNS قديم لأن التصحيح اللاسلكي أُغلق، وتُجرَّب تلقائيًا بعده المنفذ الثابت على نفس المضيف |
| اقتران QR أو الاكتشاف التلقائي لا يرى الهاتف | نسخة adb لديك بلا mDNS. تحقّق بـ `adb mdns check`، ويمكن للمثبّت جلب نسخة Google |
| أيقونة الشريط لا تظهر على GNOME | فعّل AppIndicators ثم سجّل الخروج والدخول |
| المنفذ مستخدم | تُجرَّب المنافذ تصاعديًا من 5555 إلى 5699 |
| نافذة scrcpy لا تفتح | ثبّت scrcpy أو اضبط `AUTO_SCRCPY=false` |
